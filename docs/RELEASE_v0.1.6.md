## 主要更新

1. OfferBiu 已选择的 2027 届秋招范围作为本轮来源依据。单条来源缺字段、元数据不一致或临时网络错误不再直接否决整批；可用来源继续处理，异常和不完整状态单独记录。不完整来源范围不会触发旧岗位下架，也不会偷偷回退旧公司清单。
2. 公司列表、岗位详情和评分分批提交；先保存业务结果，再推进恢复检查点。失败、空详情或无效评分不会覆盖已有有效成果。六小时仍是单段预算，满足断点与进展条件时沿原范围自动接续；暂停、取消和不可恢复错误会停止。
3. 公司列表、详情、评分默认上限分别为 10、10、6；浏览器会话默认上限为 6。同站点请求仍受限流与冷却约束。未尝试公司优先，短暂错误有限即时重试，慢超时和限流延后补跑。此为调度上限，不保证真实网站线性提速或全部岗位抓取成功。
4. 部分静态招聘入口优先用短时 HTTP 预检，Hotjob 等页面减少重复浏览器启动；动态页、登录和验证仍按浏览器及人工边界处理。进度以唯一已处理公司计数，重试不会重复加数。
5. 模型连接只保留 DeepSeek 官方服务。简历、评分和邮件的结构化输出使用官方 JSON Schema 约束并在本地严格校验；缺失评分维度不会默认写成 0 分。旧第三方兼容连接会停用，需要重新配置官方密钥；不会自动迁移或上传旧密钥。本版没有新增 PDF 图片 OCR 功能。
6. 邮件处理和官网投递复核仍由助理在当前对话回合等待并汇报。全量爬取继续后台运行，但完成、部分完成或失败后，软件运行且模型可用时会在原会话自动只读核查最终状态并给出结果摘要；不会因此启动新抓取或修改业务数据。

## 升级已有数据

已有岗位、投递记录或邮件的用户，先等待任务结束并正常退出旧版，完整备份原 `.data`。将新包完整解压到可写的短路径，不要只替换 EXE 或混用新旧 `resources`。按[已有数据升级说明](UPGRADE_EXISTING_DATA.md)迁移并核对后再使用；不要删除旧实例或原始备份。

## 验证边界

发布前使用合成数据与隔离实例验证源码、资源清单、数据库启动与重启、ZIP 完整性及校验和。真实网站响应、限流、用户网络、模型额度与输出仍可能导致局部失败；失败时保留已提交结果并如实报告，不能承诺永不失败或固定提速倍率。关闭软件或电脑后，后台任务和自动汇报都不会继续运行。
