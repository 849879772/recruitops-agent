# 已有数据的桌面版升级

适用场景：用户在旧版 RecruitOps 中已有岗位、评分、投递记录、招聘邮件或简历闪填资料，希望升级到 v0.1.7 后继续使用这些数据。

## 升级前须知

- 便携版的数据位于程序目录旁的 `.data`。其中包含 PostgreSQL 数据库、配置、凭据和备份；请将它视为私人数据，不要上传到 GitHub、Gitee、网盘或发给其他用户。
- 以下原实例复用方法仅适用于**同一台电脑、同一 Windows 用户、最终程序路径与旧版完全相同**。实例元数据记录了绝对路径，数据库凭据受当前 Windows 用户保护。换电脑、换用户或改路径不能直接照搬 `.data`。
- 不要在旧版运行、爬取或处理邮件时迁移。不要只复制 `pgdata`，也不要修改 `instance.json`、重建数据库或以管理员账户代替原用户启动。
- 一次只使用一个版本；完整 `.data` 必须在新版第一次启动前复制到位。不要将新旧 `resources` 或程序文件混用。

## 从下载到使用

以下以旧版位于 `D:\RecruitOps1` 为例；其他用户请代入自己原来的**完整路径**。

1. 等待正在运行的任务结束，从软件及系统托盘正常退出旧版，确认没有 RecruitOps 后台进程。
2. 对 `D:\RecruitOps1\.data` 做一份**完整、可读取的独立备份**，存放在本人控制的安全位置。若复制时出现“路径过长”、拒绝访问或遗漏文件，先解决备份问题，不继续升级。建议使用支持长路径的备份工具；不要把备份打进发布压缩包。
3. 下载新版 ZIP，核对发布页公布的 SHA-256，完整解压到**同一磁盘**的临时目录，例如 `D:\RecruitOps-new`。解压后应直接看到 `RecruitOps-Desktop-Preview.exe` 和 `resources`。此时不要启动新版。
4. 把 `D:\RecruitOps1` 重命名为 `D:\RecruitOps1-before-upgrade`，再把新版文件夹重命名为 `D:\RecruitOps1`。新版程序现在处于旧版的**原绝对路径**。如果新版目录中已有 `.data`，不要覆盖，先检查是否误启动过新版。
5. 在新版**第一次启动前**，将旧目录里的整个 `.data` **完整复制**到 `D:\RecruitOps1\.data`；保留旧目录和第 2 步的独立备份。最终目录应是 `D:\RecruitOps1\.data\.desktop-runtime-tests\...`，不能多套一层 `RecruitOps1` 或 `.data`。复制遇到长路径、权限或遗漏问题时不能跳过文件，必须先解决并核对完整性。
6. 用**原来的 Windows 用户**正常双击 `D:\RecruitOps1\RecruitOps-Desktop-Preview.exe`。不要选择“以管理员身份运行”，除非原实例一直由同一个管理员账户创建和使用。新版先检查数据库结构：已是最新时直接启动；已有数据库有待应用的迁移时，先生成并检查迁移前备份，再执行迁移。首次升级可能较慢，备份或检查失败会停止迁移。
7. 启动后检查原有岗位数量与样本、投递记录、已同步邮件、日程、配置、闪填资料与登录状态。已同步邮件记录在本地，但邮箱服务器上尚未同步的邮件不会因迁移自动出现；招聘网站也可能要求重新登录。

v0.1.7 的自动迁移备份只保留最近 3 份，普通重启不再重复生成完整数据库备份。这些备份只覆盖数据库，不能代替第 2 步包含配置、浏览器会话和任务资料的完整 `.data` 备份。

确认功能和数据均正常后，再按自己的备份策略清理旧程序。**出现启动失败时，不要删除 `.data`、`pgdata` 或 `instance.json`，也不要反复新建实例。**若需回退旧版，必须使用升级前的独立数据备份恢复到原绝对路径；经过新版迁移的数据库不能假定可直接由旧版读取。
