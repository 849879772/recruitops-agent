# 抓取吞吐、重试与进度优化

本轮基于 v0.1.5 源码迭代。现有的来源范围、分批写入、断点恢复和失败隔离规则保持有效。下列目标与实际交付边界分别说明，避免把可配置并发误称为已验证的实际提速。

## 调度目标

- 公司抓取保持最多 10 个并行任务；浏览器会话默认 6 个。岗位详情与评分上限保持 10 和 6。同站点 HTTP 仍为 2。
- 接口型任务与浏览器型任务分别等待各自资源。等待期间不占用另一类任务的全部执行机会。同域名任务轮换调度，遵守站点冷却和请求上限。
- 资源排队、实际抓取、批量入库、检查点保存分别计时。资源等待与网页抓取拥有独立预算，总任务仍有明确上限。
- 首次尝试优先覆盖整个公司范围。短暂请求错误最多即时重试一次；慢超时和限流延后补跑；登录、验证码、适配器不支持等永久错误不原样重试。包含首次尝试在内，默认总尝试次数最多三次。
- 已保存的完整公司不重复抓；部分公司仅补缺失内容。每次尝试的错误类型、耗时和新增岗位数进入结构化证据。重试不重复增加公司主进度。
- 公司进度按约 2–3 秒刷新，与检查点持久化频率独立；界面默认只显示已处理/总数和当前阶段。

## 正确性边界

- 完成列表不等于岗位详情或评分完成；部分抓取保留部分状态，不能触发旧岗位下架。
- 已提交成果不能被后续空结果、重试失败或异常覆盖。业务数据提交在恢复检查点之前。
- 暂停、取消和超时后停止领取新任务，释放浏览器和站点请求名额，保留可恢复范围。
- 网站明确给出的 `Retry-After` 和本地限流冷却必须遵守。不能用并发提升绕过登录或验证码。

## 验收

1. 确定性测试覆盖资源排队、跨进程名额释放、同站点公平调度、短暂错误救回、永久错误不重试、首次尝试优先、部分结果合并与重启续跑。
2. 固定同一批接口站点、浏览器站点及慢站点，对比旧的 4 公司并发、现有 10 公司/2 浏览器及新调度方案。记录耗时、完整公司数、有效岗位数、限流和内存峰值；结果质量不能下降。
3. 原生测试包在独立实例完成 initdb、启动、停止、重启、持久化与打包资源检查。正式版和当前运行的测试实例不在本轮替换范围内。

离线夹具只能证明调度与恢复行为；真实网站吞吐提升须由同范围、同条件的实测确认，不预设倍率。

## 已实现的行为

- 浏览器会话默认 6、最高配置到 6；同域名 HTTP 仍为 2。跨进程锁及异常释放保留。资源等待最多额外 60 秒，抓取 worker 回传有界的浏览器/HTTP 等待耗时。此项在停止中的任务之后调整，旧候选包及当时的实测基线仍为默认 4。
- 调度器让未尝试的公司优先进入队列，按入口域名公平选择；明确 `render` 的入口受浏览器名额约束。短暂错误最多即时重试一次，慢超时和部分结果延后补跑；同一冻结范围跨续跑最多三次尝试。补跑有 50 家及 180 秒的调度预算，不能长期阻塞详情阶段。
- 大范围（至少 100 家）采用紧凑索引与原子写入的逐公司回执。索引只记录状态、次数和回执哈希，已提交岗位保存在公司回执。旧版大型断点在续跑时先写回执、最后原子切换索引；迁移失败保留旧格式继续运行。索引与回执按作用域、公司 ID 和哈希验证，损坏不会被当作已完成。
- 工作台从已提交的计数更新公司进度，约每 2.5 秒刷新，不为了界面轮询反复解析大型检查点。
- 后续效率修复在未识别的通用入口先做最多 5 秒 HTTP 预检。静态页若出现已注册招聘平台链接，直接运行对应适配器；空壳与动态页面保留浏览器回退，登录、验证和限流状态不能被当作有效岗位。HTTP 429 会进入延后重试。
- Hotjob 和 Ourpalm 的连续列表渲染可在同一公司 worker 中复用一次 Chromium，页面上下文逐次独立；切换 HTTP、异常及 worker 退出时释放浏览器名额。有明确目标选择器的渲染可在 DOM 就绪后等目标元素；无选择器和显式要求 `networkidle` 的页面保持原等待方式。
- Hotjob 在 title-first 公司列表阶段只提取岗位标题、稳定链接和分页证据，逐条 JD 由后续统一详情阶段补齐；直接调用适配器仍保留原行为。其 API 429 不继续渲染重试，渲染单页不能冒充完整分页。

## 尚未证明或未覆盖

- 部分适配器在开始后才转入浏览器，调度器无法提前精确分成接口与浏览器两个队列；底层浏览器限额继续约束实际启动。
- 部分适配器自己的网页超时仍可能把资源排队时间算进去。额外的 worker 等待预算不能保证每个网站都获得完整独立的页面执行时间。
- 按站点自动从 2 个请求提升至 3–4 个仍需同范围压力对照，本轮没有启用；浏览器默认 6 的真实站点效果也仍需同范围测试及内存/限流观察。
- 旧版小范围检查点保留 v1；真实网站吞吐、JD 完整率和评分成功率不能由离线夹具推出。
- 这轮效率修复尚未用相同冻结来源范围做新旧测试包的真实网站对照；浏览器启动减少与列表阶段详情请求延后由确定性测试证明，不据此宣称整体运行时间缩短固定比例。
