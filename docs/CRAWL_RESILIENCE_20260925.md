# 抓取容错、分批保存与并发优化

日期：2026-09-25。基于当前 v0.1.5 源码继续修改，保留此前修复；不是覆盖已发布 v0.1.5 的声明。

## 行为变化

- OfferBiu 以实际请求的 2027 届、秋招及行业筛选为来源范围。单条元数据不一致不再拖停整批；未经筛选的导入仍需范围校验。
- 缺 ID、缺公司名、坏结构和冲突记录隔离；重复记录去重。异常计数与原因保留在结构化结果中。
- 网络、可重试 HTTP 和 JSON 解析错误进行有限退避重试。遵守 Retry-After；超出等待预算时保留部分成果，不提前请求。
- 分页总数变化进行有界补查，不能确认完整时如实标记 partial。受限预览不作为正常页应用。
- 来源检查点按筛选条件绑定，24 小时有效，恢复时重读重叠页。已遍历结束但仍 partial 的新任务重新核实全部来源；损坏缓存保留诊断副本后重读。
- 可用的部分来源可以继续抓取，但本轮结果始终保留“部分完成”；续跑不扩大冻结范围，不把历史完整快照当作本轮新结果。
- 部分来源范围禁止驱动旧岗位下架。公司范围构建、检查点或新流水线初始化失败时，拒绝运行旧公司配置。
- 已筛选的岗位列表先保存待补全记录；详情和评分按数量或时间分批提交。先提交数据，再推进恢复检查点，重放保持幂等。
- 失败不能用 pending、空详情或无效评分覆盖已有有效成果。后续事务失败只回滚该事务，不撤销此前已提交批次，不修改投递记录。
- 主检查点原子替换、有限重试并保留上一份备份；损坏的公司详情侧车只影响该公司，主范围无法验证仍拒绝盲目恢复。
- 公司主进度统计唯一已尝试公司，失败和部分完成也计入已处理；重试不重复计数。来源范围未确认前不展示误导性百分比。

## 并发与资源

| 参数 | 默认值 |
| --- | ---: |
| crawl_max_concurrency（公司列表） | 10 |
| detail_max_concurrency（详情） | 10 |
| match_max_concurrency（评分） | 6 |
| browser_max_concurrency（浏览器会话） | 2 |

旧的显式配置保持兼容，不强制覆盖个人已设参数。并发是上限，不保证始终满载或线性提速。

独立抓取 worker 中的 requests 请求按 hostname 共享跨进程 2 个令牌，包括适配器内部线程；连续故障和限流共享退避。浏览器使用独立的跨进程会话池，进程退出后操作系统自动释放锁。

边界：Chromium 内部静态资源不是逐请求限流；绕过独立 worker 的直接 requests 调用不在此池中。模型请求沿用已有重试，不影响邮件等其他模块。资源状态仅存站点冷却和锁，不使用业务数据库。

## 验证要求

- 合成分页：坏行、去重、冲突、总数变化、网络/JSON 重试、受限页、检查点失效与范围变化。
- 临时数据库：部分来源继续、禁止旧公司回退、禁止不完整范围下架、投递记录不受影响。
- 崩溃边界：先提交后检查点失败、详情已提交后中断、评分失败、旧评分保留、侧车局部损坏、重复续跑。
- 并发边界：10/10/6 参数传递、适配器嵌套线程限流、跨进程浏览器/HTTP 上限、退出归还、显式浏览器上限 1。
- 前端：已处理计数、来源不确定百分比、部分完成与跳过状态，终态任务不自动附着到新会话。
- 打包：新增模块在源文件清单中、资源哈希校验、隔离的新实例启动/正常退出/重启，不能使用正式实例数据测试。

测试均优先使用确定性夹具。未用真实招聘网站、真实模型配额或用户业务数据证明吞吐量；不可宣称所有网站都不会失败。
