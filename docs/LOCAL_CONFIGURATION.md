# 本地配置与分发

左侧「配置」集中管理模型 API、评分开关、求职助理开关、个人简历和标题关键词、IMAP 邮箱，以及 CSV/JSON 投递导入。

模型统一为 V4.1 Flash，API 标识 `deepseek-flash`。评分、邮件、助理和视觉共用 API 密钥及服务基础地址；各协议路径自动派生，不再提供分项模型/接口输入。旧分项模型值加载时归一，保存后清理旧配置键；基础地址支持结尾 `/v1`，自动规范化。

## 生效范围

- 保存后的覆盖配置位于 `.data/settings/preferences.json`；API 密钥及邮箱授权码为本机文件中的敏感数据，读接口只返回是否配置，空密码框不会清除已有密钥。
- 个人资料保存在 `.data/settings/candidate_profile.yaml`。简历上传支持文字 PDF 和 UTF-8 TXT/MD，不调用模型；先提取到编辑框，核对并保存后才作为评分资料。扫描件、加密或无正文文件会明确拒绝。
- 标题包含关键词非空时，取代内置方向关键词；命中任意一项即可。自定义排除词、实习和博士排除优先。留空时使用已有方向规则。
- 新流水线读取新配置；常驻助理、MCP、邮箱服务需要在当前任务完成后重启 API。不得为使配置生效中断正在进行的全量抓取。
- 修改个人资料不会自动重算已有评分，也不会删除已有岗位。不同用户应该使用全新数据卷，避免沿用原用户的匹配分数和投递记录。
- 投递导入接受 CSV 模板或 JSON 对象数组，字段为 `company_name`、`job_title`、`stage`、`record_url`。同公司同标题只跳过，不覆盖阶段。笔试对应 `written`，测评对应 `applied`。整批验证失败不写入。

## 定时任务

全量抓取使用项目的同一正式流水线直接运行，不再依赖聊天轮次的 600 秒超时。公司请求、详情请求和评分仍保留各自的超时与检查点，不能把整轮耗时长误判为失败。

定时任务页只展示最近一轮紧凑统计；新一轮结束时原子替换 `.data/runtime/latest-scheduled-crawl.json`，不保留统计历史。执行审计、断点与业务数据不因此删除。完成通知为页面内通知，页面关闭时，下次打开后仍能看到最近结果，不是短信或邮件推送。

公司数按公司计，入口数按 URL 计，两者不一定相等。新增公司和新增入口分别展示。完整列表但有详情失败的公司显示部分成功；流程执行完成不等于所有公司和评分均成功。缺失统计显示“未记录”，不伪造零值。

## 给其他人部署

不要把当前目录、当前 Docker 镜像或数据库卷直接整体发送：它们可能包含个人简历、API 密钥、浏览器 Cookie、邮箱正文、旧评分与投递记录。

分发源代码时只带应用代码、依赖声明、迁移和启动脚本；用空的个人资料模板替换 `config/candidate_profile.yaml`，使用空公司目录 `companies: []`，由第一次 BIU 发现注册公司。使用不含密钥的 `.env.example`，根据接收方平台配置 Codex 命令；Docker 部署使用容器内命令。使用新的 Compose 项目名和全新数据卷，再从配置页输入接收方个人资料。不要分享 `.env`、`.data`、旧数据库、日志、浏览器配置、默认简历、扩展本地绑定密钥或历史测试输出。

当前新增配置入口并不等同于已制作、审计一个可公开分发的安装包；正式分发前仍需在空目录/空数据卷上验收初次启动。
