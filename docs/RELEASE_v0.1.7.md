## 主要更新

1. **官网投递复核更完整。** 结合页面文字、岗位卡片和必要的截图模型识别，校验证据是否属于当前岗位；不把其他岗位状态或流程中的未来步骤作为当前进展。新增“查看复核明细”和“查看待核对”，可查看保留原阶段的原因、人工确认本地投递与官网岗位的对应关系。需要登录时可打开官网，登录后只重新复核该公司本次列出的岗位。
2. **招聘邮件同步、识别与人工确认更清楚。** 手动同步读取邮箱最新内容，并分别报告新增、已有和同步失败。临时模型错误采用有限重试；失败邮件可明确选择后重新识别。对于未指定岗位的同公司测评或笔试邮件，可由用户确认关联多个投递，并共享一项日程；有明确岗位的邮件仍按该岗位证据处理。确认后沿原任务继续，保留已提交结果，避免重复创建日程。
3. **定时任务启动与追问更可靠。** 全量抓取和健康检查先保存本地任务会话并启动流程，不再把模型工具握手作为启动前提；评分仍需要模型可用。需要模型的任务仅对临时启动错误做有限重试，持续失败会保留可查看的原因。任务报告在重启后仍可打开，追问使用原任务上下文。
4. **部分完成按真实成果汇报。** 全量流程结束时，区分完成、部分完成和失败，保留新增岗位、已有岗位刷新及评分完成/未完成统计。不会把 `partial` 一概写成失败，也不会把保留原阶段或需要人工核对的投递冒称为官网已确认无变化。
5. **登录状态与诊断保留更有边界。** 内置招聘浏览器定期保存 Cookie，正常退出时再次保存；会话 Cookie 在当前 Windows 用户与浏览器目录下加密恢复，最长 7 天，仍受官网退出登录和失效规则影响。软件运行且没有业务任务执行时，会分批清理或压缩超过 12 小时的复核页面、截图相关诊断及工具追踪，保留业务阶段历史、最新复核摘要和仍需恢复的任务证据。
6. **启动和看板更轻。** 启动先检查数据库迁移；结构已是最新时不再每次生成完整备份。已有数据库需要结构迁移时，先备份并检查归档，再迁移，自动迁移备份保留最近 3 份。已入库岗位不会因当前简历关键词变化而在浏览时被重新隐藏；投递看板自动读取后续分页、准确区分总数与已加载数量，并减少刷新时重复构建卡片。

## 升级已有数据

先等待任务结束，从软件和系统托盘正常退出旧版，完整备份原 `.data`。新版完整解压后，在**首次启动前**复制整个旧 `.data`，不能只复制数据库；最终程序应回到旧版的相同绝对路径，并使用原 Windows 用户启动。具体步骤见[已有数据升级说明](UPGRADE_EXISTING_DATA.md)。

一次只使用一个版本。不要只替换 EXE、混用新旧 `resources`，或在运行时复制数据库。启动时的迁移备份不能代替升级前的完整 `.data` 备份；确认岗位、投递、邮件、日程、配置与登录状态后，再处理旧程序和备份。

## 使用与验证边界

本版已通过隔离的原生运行时与打包 EXE 首次启动、重启、匿名配置与记录保留、数据库备份恢复验收；ZIP CRC、文件集合与内部完整性清单逐项验证通过。公开测试初次完整运行 4705 项通过、5 项跳过、3 项旧调用次数断言失败；最小修正断言后，相关两文件的 58 项测试复测全部通过。未重复运行整个公开测试集，未把这些离线测试当作真实官网或模型的全兼容保证。

真实招聘网站、网络、登录验证和模型输出仍可能造成局部失败，不能保证所有网站兼容或 AI 始终识别正确。证据不足时保留已确认阶段并报告原因；人工确认岗位对应关系也不等于确认进度。复核截图会遮挡输入框和可识别的联系信息，再用于模型分析，请按自己的隐私需求使用相关功能。

软件和电脑需要保持运行，关闭后不会继续抓取或执行定时任务。已有登录状态也不能绕过官网的验证码、注销或账号限制。发布核验应使用离线页面、合成数据和隔离实例；发布包校验和以本页与随包校验文件为准。
